# 测试策略与端到端验收

## 分层证据

| 层 | 本项目检查点 | 不能代替 |
| --- | --- | --- |
| Schema/CLI | 五类 JSON、UPDATE 互斥、SUPPLY_FIELDS、结果字段、错误退出 | MCP 真实协议 |
| Fake Provider + SQLite | 校验与状态机、重启恢复、幂等、同用户冲突、授权拒绝、UNKNOWN | 会畅 API 行为 |
| httpx MockTransport | 会畅接口 URL、表单、GMT、MD5 Token、错误映射 | 真实网络及会畅鉴权 |
| MCP Client/Inspector | initialize、tools/list、tools/call、structuredContent、Header 上下文 | 腾讯 ADP 在线兼容 |
| 真实会畅测试站点 | 创建、修改、冲突、重复请求、回读、不同 userId | 企业微信与 ADP |
| 腾讯 ADP + 企微 E2E | 真实用户消息、跨轮 pending、动态身份与实际回执 | 全部并发故障覆盖 |

本地命令：

```bash
python -m pytest -q
python -m ruff check src tests
python -m compileall -q src
python -m meeting_reservation validate-examples --dir examples
```

这些命令的结果必须以本次实际环境的输出为准；本文件不宣称此前未执行的层通过。

## 核心验收清单

- **AC01**：有权限用户创建一场会畅会议，返回真实 confId、会议号和参会链接，写后回读。
- **AC02**：CHECK 只读，不创建；用户没有标题也能检查空闲。
- **AC03**：缺少结束时间 → NEED_INPUT → SUPPLY_FIELDS → 继续创建或冲突。
- **AC04**：不同企微 UserID 在同时间可各自订会（取决于真实容量）；同一 userId 重叠被拒绝。
- **AC05**：UPDATE 平移时间且修改名称，保留原会议 Id，不新增会议。
- **AC06**：仅修改名称走 confModify，不误用不能修改时间的接口；修改时间走 confModify2。
- **AC07**：真实虚拟 roomId 的指定资源预约和改会通过；普通实体 A301 不会误转成会畅 roomId。
- **AC08**：不同用户不能修改或继续他人的会议/待处理申请。
- **AC09**：重复 operation_id + 同 payload 不重复提交；同 ID + 不同 payload 拒绝。
- **AC10**：写请求超时、服务器重启、远端成功但回读失败时，不发生自动重复创建；UNKNOWN 可核实。
- **AC11**：多用户争用资源、同会议并发 UPDATE 的真实冲突行为在会畅测试环境验证，不把单实例 SQLite 锁当成会畅原子保证。
- **AC12**：ADP 真实识别创建/修改、响应状态分支、跨轮补参及企微正确显示；缺失用户身份拒绝写入。
- **AC13**：已取消/过期/旧 revision pending 拒绝，非法补参不吞掉可恢复的申请。
- **AC14**：普通未支持字段（参会者邀请/会议描述）必须明确拒绝，不静默丢弃。

## 质量门禁

对可在本地运行的层执行真实命令并保留版本、环境、结果；真实 Provider/ADP 测试需要 Owner 批准的隔离资源与凭据。没有安装 MCP SDK 或没有 ADP 测试租户时，**MCP 在线握手和 E2E 明确未验证**，不能以 Fake 绿色替代。

本仓库未新增 CI 工作流；若后续需要自动化 CI，应依据项目实际门禁另行授权。
