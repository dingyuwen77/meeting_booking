# 测试与联调验收

本页说明如何取得各层证据。需求及完成状态唯一维护在 [roadmap/01_实施路线图与任务状态.md](../../roadmap/01_实施路线图与任务状态.md)，不在测试教程再维护一套验收编号。

## 本地验证

先按 [docs/operations/01_本地运行与调试.md](../operations/01_本地运行与调试.md) 安装并激活虚拟环境，然后执行：

```bash
python -m pytest -q
python -m ruff check src tests
python -m compileall -q src
python -m meeting_reservation validate-examples --dir examples
```

若宿主沙箱无法写系统临时目录，可先创建项目内临时父目录，再用 `python -m pytest -q --basetemp=.test-tmp/run`；每次选择本任务专用路径，pytest 会重建该路径，不能指向用户数据目录。

| 证据层 | 生产入口与检查内容 | 证明边界 |
| --- | --- | --- |
| Schema / CLI | [tests/test_contracts.py](../../tests/test_contracts.py)、[tests/test_unified_update.py](../../tests/test_unified_update.py)、[tests/test_cli.py](../../tests/test_cli.py) | 五类消息、组合 UPDATE、时间、非法值、退出码 |
| Fake + 真实 SQLite | [tests/test_booking_service.py](../../tests/test_booking_service.py) | 创建/修改/选择/补参、身份、幂等、重开数据库、受控并发、未知结果 |
| HTTP Mock | 同一业务测试文件调用生产 BizVideoProvider | 请求端点、表单、GMT、Token、畸形响应与写入不确定性；不证明会畅当前接受这些字段 |
| 真实 MCP HTTP 协议 | [tests/test_mcp_runtime.py](../../tests/test_mcp_runtime.py) | SDK ASGI 生命周期、initialize、五个工具发现、正式 Schema、签名、structuredContent、重试查询、取消与跨用户拒绝 |
| 正式包 / 容器 | wheel 安装、`meeting-mcp` 入口及 Docker 启动 | 包内 Schema、非源码目录导入、实际进程与 HTTP 握手 |

MCP 回归只替换供应商网络边界：身份、业务、Schema、SQLite 和 SDK 都是生产实现。它不等于真实会畅、腾讯 ADP 或企业微信验收。并发测试用同步事件/屏障固定交错位置，只证明本地操作号及 pending 消费；不证明不同操作号或外部渠道的会畅提交原子性。

## 真实会畅测试

在业务方批准的隔离站点执行，并保留脱敏的部署版本、供应商文档版本、时间范围、请求类型、返回状态与回读结果。密钥、Token、身份 Header、密码和敏感入会链接不入测试记录。

1. 先只读核对站点权限、可用容量、用户列表与详情字段，并与供应商原 PDF 复核端点及响应结构。
2. 两名企微测试成员分别预约同一时段，确认 userId 原样复用与实际资源约束；同一成员的重叠预约应被拒绝。
3. 验证普通名称修改、相对与绝对时间修改、指定虚拟 roomId、回读、会议号保留及其他已知选项未被覆盖。
4. 验证资源争用、同会议并发 UPDATE、连接中断和写后回读失败，核实会畅原子性、版本控制与人工对账路径。
5. UNKNOWN 只能查询原操作并由有权限的人核对会畅后台；本服务没有自动对账改写台账或安全重放功能。不能换 operation_id 碰运气重建。

## ADP / 企微验证

按 [docs/integrations/02_腾讯ADP与MCP接入.md](../integrations/02_腾讯ADP与MCP接入.md) 在测试应用验证工具发现、Schema、结果字段、失败分支、稳定操作号、跨轮 pending 与两名成员的可信身份。必须保留真实画布/部署版本和用户可见结果，不能用本地工具测试代替。

真实站点、网关、ADP 和企微证据齐全之前保持写入关闭；生产启用条件见 [docs/operations/02_部署与故障恢复.md](../operations/02_部署与故障恢复.md)。仓库目前没有 GitHub Actions 工作流，远程没有检查任务不代表 CI 通过；本地命令和合并后 revision 的验证应写入 PR。
