# 测试与联调验收

## 先区分“代码存在”“本地测试通过”和“外部系统真实可用”

本仓库的 MCP/业务/SQLite/会畅 HTTP 映射可以由隔离测试验证，但真实会畅、腾讯 ADP 租户和企业微信网关属于不同的失败边界。**任何一层的 Fake/Mock PASS 都不能自动升级为下一层的实测通过**。需求编号和当前未完成门禁唯一维护在 [roadmap/01_实施路线图与任务状态.md](../../roadmap/01_实施路线图与任务状态.md)；本页只讲如何取得证据。

## 1. 本地无真实会畅副作用的回归

按 [docs/operations/01_本地运行与调试.md](../operations/01_本地运行与调试.md) 安装 `.[dev]` 并激活虚拟环境后：

```bash
python -m pytest -q
python -m ruff check src tests
python -m compileall -q src
python -m meeting_reservation validate-examples --dir examples
```

这些是项目现有的验证**命令入口**，不是本次文档治理已实际执行的证明。若沙箱系统临时目录不可写，pytest 可在核对路径且确保不覆盖用户数据之后指定项目内专用 `--basetemp`；测试运行记录要保留真实命令、环境、exit code、结果和对应 commit。

| 证据层 | 现有测试/入口 | 可以证明什么，不能证明什么 |
| --- | --- | --- |
| Schema 与 CLI | [tests/test_contracts.py](../../tests/test_contracts.py)、[tests/test_unified_update.py](../../tests/test_unified_update.py)、[tests/test_cli.py](../../tests/test_cli.py) | JSON 契约、时间顺序、UPDATE、CLI 错误/退出码；不证明真实会议会创建 |
| 业务 + 真 SQLite | [tests/test_booking_service.py](../../tests/test_booking_service.py) | Fake Provider 下创建/修改/冲突、幂等、pending、重启恢复和受控线程并发；不证明会畅提交原子性 |
| 会畅 HTTP Mock | [tests/test_booking_service.py](../../tests/test_booking_service.py) 里的 `httpx.MockTransport` | 生产 Provider 发出的 GET/POST/form、Token、GMT 与畸形响应处理；不证明当前会畅站点实际接收 |
| MCP 协议 + 业务链 | [tests/test_mcp_runtime.py](../../tests/test_mcp_runtime.py) | 真实 MCP SDK ASGI `initialize` / Tool 发现/调用、签名、Schema、结构化结果、业务/SQLite/Provider 接线；供应商网络仍隔离 |
| 临时身份参数探针 | [tests/test_mcp_runtime.py](../../tests/test_mcp_runtime.py) | 默认隐藏且不可调用、开启后发现、独立配置、专用 Header 每次校验、UserID 原样回显与非法输入拒绝、业务/SQLite/外网副作用守卫；不证明 ADP 已绑定可信用户 |
| 源码之外的安装/容器 | [pyproject.toml](../../pyproject.toml)、[Dockerfile](../../Dockerfile)、[compose.yaml](../../compose.yaml) | 需要单独运行隔离安装、构建、进程/容器启动和 MCP ping；不能用源码 pytest 冒充构建成功 |

测试文件存在不意味着对应 runner 已在**当前 revision 与目标环境**执行通过。文档变更只需针对性核对事实、目录/链接、命令与示例兼容；不因文字重组无条件访问远端 API 或开启写入。

## 2. 真实会畅验收：必须业务方批准

前置：取得供应商原 PDF/版本、专用测试站点、实际权限、测试成员/用户 ID、资源容量和明确的受控写入许可；在结果记录中脱敏，不能上传 APIKey、Token、签名 Header、会议密码或敏感加入链接。

按风险和依赖顺序取证：

1. 只读核对账号身份、站点权限、GET/POST 端点、资源与会议列表结构、GMT 时间；实际响应与记录的 v1.0.10 映射逐项比对。
2. 验证本人已预约重叠和资源池空闲查询；确认 CHECK 不写会畅但有可能存储本地操作号与 pending。
3. 使用隔离资源执行 CREATE，按返回会议 ID **重新回读**确认归属、会议号、名称、开始时刻、时长、加入链接等结果。
4. UPDATE 验证仅名称、相对时间/绝对时间、指定虚拟 roomId 与复杂会议原有配置保留。特别核对 `keepConfNo=1` 在真实站点的实际结果。
5. 执行受控资源竞争、相同操作号并发、不同操作号冲突、断连/写后回读失败模拟与人工对账演练。供应商 exactly-once / 乐观版本 / 原子提交没有证据时不能声称成立。

真实写入结果不明时应执行 [docs/operations/03_故障排查与恢复.md](../operations/03_故障排查与恢复.md)，不可更换 operation_id 盲目重复创建。

## 3. ADP / 企微真实端到端验收

先用本地 MCP 客户端验证协议，接着在实际腾讯 ADP 测试应用中验证：

- 真实 `tools/list` 是否可识别五个工具以及展开的入参/出参 Schema。
- 临时参数 POC 开启时另检查 `identity_binding_probe`；分别传入两名用户并尝试聊天覆盖身份，核对实际工具参数和回显。只证明传递边界，不代替下一项的可信身份认证；操作见 [docs/integrations/02_腾讯ADP与MCP接入.md](../integrations/02_腾讯ADP与MCP接入.md)。
- 能否产生正确的 `request` 参数，消费 `structuredContent.status`、确认摘要、冲突和错误分支。
- 能否跨轮持久关联同一成员的 pending ID/revision/有效期，以及为每一次新决定生成稳定业务操作号。
- 企微可信网关是否能对不同员工**独立认证并动态签发** Header，且 ADP → MCP 每轮确实收到正确签名。静态 Header/模型自报用户 ID 不合格。
- 在真实会畅测试站点、受控权限与写入授权下，最终用户是否看到真实创建/修改/冲突/UNKNOWN 的正确反馈。

具体连接步骤及与网关的责任边界见 [docs/integrations/02_腾讯ADP与MCP接入.md](../integrations/02_腾讯ADP与MCP接入.md)。

## 4. 证据记录和完成判断

每次真实验证至少记录：目标 commit/容器镜像、Python/MCP SDK/目标环境、命令或调用路径、脱敏输入、预期输出、实际输出、exit code/状态、日志位置、时间、测试者与结论。对照 R01–R12 逐项记录本地证据和外部待验收项；不能用 PR 描述、测试函数名或历史“全部通过”代替本次结果。

- Git 仓库交付：另行检查当前 PR、合并权限、适用 required checks 与合并后的 main revision。当前仓库**没有 GitHub Actions 工作流**，不能把“没有自动 check”写成 CI 绿色。
- 生产启用：必须同时满足真实站点、可信网关、ADP/企微 E2E、持久化/恢复和环境授权；保持 `MEETING_WRITE_ENABLED=false` 直到门禁完成。
- 文档或代码与正式需求冲突时，先分析事实是文档过期还是实现缺陷；不得只修改解释消除表面差异。
