# ADP ↔ MCP 会议接口契约 V1

## 1. 边界与唯一事实源

- **ADP 语义层：** 识别 `CREATE`、`UPDATE`、`CHECK`、`OTHER`，生成 `meeting.intent.v1`。
- **可信调用层：** 提供稳定 `operation_id`，依据接入方式传递可验证操作者上下文；本阶段不假设 ADP 的请求 ID 等同于可重复业务操作 ID。
- **MCP 服务端：** 校验 Schema/权限、解析资源、查询冲突并在真实会议系统支持的提交边界进行写入。
- **会议系统：** 真实会议、资源、权限和版本的最终事实源。
- **机器契约：** `../src/meeting_reservation/schemas/` 下 5 份 JSON Schema。本文不复制完整属性定义；字段合法性以 Schema 为准。

## 2. 五种消息

| kind | schema_version | 用途 |
|---|---|---|
| `intent` | `meeting.intent.v1` | ADP 只表达业务意图，不带身份/操作 ID |
| `request` | `meeting.request.v1` | `submit_meeting_request` 入参：操作 ID + 意图 |
| `continue` | `meeting.continue.v1` | `continue_meeting_request` 入参：持久申请 ID、版本和选择 |
| `operation-query` | `meeting.operation-query.v1` | `get_meeting_operation` 入参：原始操作 ID |
| `result` | `meeting.result.v1` | 所有业务工具的结构化响应 |

此处名称为应用层契约，不代表 MCP 工具已真实部署。MCP 的 `inputSchema`/`outputSchema` 由未来服务端从这些 Schema 取得或保证等价。

### 创建 / 查询 / 修改

- `CREATE` 和 `CHECK` 的 `meeting` 对象有固定字段，允许 `title`、`start_at`、`end_at`、`timezone`、`room_query` 为 `null`，以表达尚需补充的信息。
- `CHECK` **只查询**，不应产生创建副作用。
- `UPDATE` 使用 `target` 定位会议，可以是 `meeting_id` 或自然语言 `search_text`；当无法唯一定位时，服务端必须返回待选择状态。
- `UPDATE` 统一使用 `update: {"time_shift_minutes": ..., "changes": {...}}`，**不再使用 `mode=SHIFT/PATCH`**。两个键都必须出现；`time_shift_minutes` 为 `null` 表示不平移，非零整数按分钟整体移动开始和结束时间（正数推迟、负数提前）。
- `changes` 是字段差量对象：未出现字段保持原值；`attendee_queries` 若出现表示完整替换名单；`description:null` 表示明确清空。允许 `time_shift_minutes` 与非时间字段组合，例如推迟 60 分钟并将会议室改为 A302。
- **防歧义约束：** 存在非空时间偏移时，`changes` 不能包含 `start_at` 或 `end_at`；`time_shift_minutes:null` 且 `changes:{}` 的空更新非法；`time_shift_minutes:0` 非法。JSON Schema 直接强制这些条件，Python 校验器负责同时给出绝对起止时间时的时序比较。
- 仅识别到 `UPDATE` 但缺少具体修改参数时允许 `update:null`，表示仍需补充用户信息；这不是可直接提交的更新指令。
- 参考示例：`../examples/update-relative.intent.json`、`../examples/update-fields.intent.json`、`../examples/update-combined.intent.json`。
- `OTHER` 表示非会议业务，不应调用写操作。

### 时间和资源

- 绝对时间使用含显式数值时区偏移的 ISO 8601，例如 `2026-11-05T14:00:00+08:00`。同时保存 `timezone`（例如 `Asia/Shanghai`）作为业务时区提示。时间字符串不允许无偏移的本地时间。
- 在同一消息中同时存在起止时间时，Python 校验器按真实绝对时间比较并要求 `end_at > start_at`。
- 只有一端时间时可以通过结构校验，**不代表已准备好提交**。结合原会议持续时长的修改规则需要阶段 3 实现。
- `room_query` 和 `attendee_queries` 是待解析自然语言标识；不能把名称直接当成可靠资源 ID。
- 仅 Schema 合法不意味着会议可创建。业务完整性、参会者解析、授权和冲突仍属于 MCP 业务层责任。

### 身份与操作 ID

- `operation_id` 由可信调用层生成，重试同一业务操作时保持不变；新用户决策使用新的操作 ID 但引用原待处理申请。
- 生成者必须解决多轮/重试时的 ID 稳定性，不能默认 `SYS.RequestId` 就是跨重试幂等键。
- JSON 中故意没有 `user_id`、`tenant_id`、`is_admin` 可信字段。任何接入层传入的身份断言都要由服务端验证后使用。
- 已验证身份和待处理申请绑定，在服务端二次检查权限、申请版本与资源状态。群聊和跨用户操作不得依靠对话内容决定权限。

### 继续处理

- `SELECT_OPTION`：传入 `pending_request_id`、`expected_revision` 和 `option_id`。
- `CANCEL`：取消当前待决策申请，不取消其他人的真实会议。
- 当前 V1 只覆盖**选择已生成选项或取消**。用户提出新的自由文本时间/会议室，需在后续阶段约定新申请/修订路径，不能默认为已有选项；扩展需新增契约版本或兼容字段。

## 3. 状态语义与 ADP 分支

| status | 语义 | ADP 操作 |
|---|---|---|
| `COMMITTED` | 已确认创建/修改，必须存在真实 `meeting_id` | 展示成功及会议 ID |
| `AVAILABLE` | 只读空闲查询为可用 | 告知用户，不建会 |
| `UNAVAILABLE` | 只读空闲查询为不可用 | 告知用户，不建会 |
| `CONFLICT` | 写操作冲突，存在持久待决策申请 | 提供真实选项 |
| `NEED_INPUT` | 缺少业务参数，存在待决策申请 | 追问 |
| `NEED_SELECTION` | 会议、人员等匹配不唯一 | 让用户确认候选 |
| `DENIED` | 权限不足 | 拒绝 |
| `INVALID` | 结构之外的业务规则不满足 | 解释需要修正的字段 |
| `EXPIRED` | 待处理申请过期 | 重新校验 |
| `IN_PROGRESS` | 原操作仍执行中 | 继续查询，不再次新建 |
| `NOT_FOUND` | 查询的操作或会议不存在 | 区分场景，不能误判成功 |
| `UNKNOWN` | 写操作结果尚不确定 | 查询原操作状态或人工核实 |
| `FAILED` | 已确认失败，必须包含错误码和可重试标记 | 受控处理 |
| `CANCELLED` | 取消了待处理申请 | 告知用户 |

`CONFLICT`、`NEED_INPUT` 和 `NEED_SELECTION` 必须携带 `pending_request_id`、`pending_revision` 和 `expires_at`，为后续多轮处理提供可恢复数据。若没有可行备选方案，`options` 可以为空，允许用户取消或重新发起，但不能虚构资源。

错误对象使用 `error.code`、`error.message` 和 `error.retryable`；`retryable` 并不授权盲目重复写入，仍应根据操作 ID 查询已有执行状态。

## 4. 本阶段可验证 / 不可验证

**当前可验证：** JSON Schema 文件本身合法、成功与失败示例、未知字段拒绝、版本/枚举限制、条件结果字段、时间范围判断、CLI 正常/错误退出。

**阶段 2/3 才能验证：** 腾讯 ADP 对 `$ref` 或工具结果的实际支持、可信企微成员身份、MCP 网络协议与真实 `tools/list`/`tools/call`、会议系统提交原子性、幂等持久化、冲突后跨轮恢复、真实会议创建和修改。

## 5. 兼容与版本

当前 `v1` 为**待与 MCP/会议系统负责人复核的契约候选**，并未对外正式发布。此次在同一候选版本内用统一 `update` 取代原 `SHIFT/PATCH` 双模式，旧结构不再兼容，消费者必须改用新结构后才能继续接入。冻结前仍需确认真实会议系统字段、授权能力与修改语义；一旦正式发布，破坏性调整必须新开版本。

已发布后如变更字段含义、结果条件、时间语义或破坏现有消费者，应发布 `v2` 并约定迁移，不静默改变 V1。测试示例与 Schema 应同版本维护。
