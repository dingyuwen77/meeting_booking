# 标准化会议协议

## 为什么有独立协议

ADP 输出的是模型理解后的语义，MCP/业务服务需要可校验且可跨轮保存的结构；会畅的字段与错误格式则只留在 Provider 内。**正式字段源只有五份版本化 JSON Schema**，Markdown 解释用途、校验边界和实际执行能力，不手抄第二套字段表。

| 契约 | 输入/输出职责 | 机器事实 |
| --- | --- | --- |
| `meeting.intent.v1` | ADP 提取 CREATE、CHECK、UPDATE、OTHER 的语义，不含可信身份 | [src/meeting_reservation/schemas/meeting-intent.v1.schema.json](../../src/meeting_reservation/schemas/meeting-intent.v1.schema.json) |
| `meeting.request.v1` | 可信调用层附加稳定 `operation_id` 后提交 | [src/meeting_reservation/schemas/meeting-request.v1.schema.json](../../src/meeting_reservation/schemas/meeting-request.v1.schema.json) |
| `meeting.continue.v1` | 引用 pending 与 revision，补字段、选候选或取消待决策请求 | [src/meeting_reservation/schemas/meeting-continue.v1.schema.json](../../src/meeting_reservation/schemas/meeting-continue.v1.schema.json) |
| `meeting.operation-query.v1` | 按原操作号读取已存状态，不重放写入 | [src/meeting_reservation/schemas/meeting-operation-query.v1.schema.json](../../src/meeting_reservation/schemas/meeting-operation-query.v1.schema.json) |
| `meeting.result.v1` | 业务统一状态；只有 COMMITTED 携带确认后的会议详情 | [src/meeting_reservation/schemas/meeting-result.v1.schema.json](../../src/meeting_reservation/schemas/meeting-result.v1.schema.json) |

[源码：src/meeting_reservation/contract.py](../../src/meeting_reservation/contract.py) 通过 JSON Schema Draft 2020-12 校验并补充跨字段时间顺序检查；MCP 工具发现时展开包内引用，业务工具入参外层是 `{"request": ...}`，`structuredContent` 是相应结果。见 [src/meeting_reservation/mcp_server.py](../../src/meeting_reservation/mcp_server.py)。

## 业务字段与执行能力的区别

- **CREATE** 需要标题、起止时间；Schema 允许缺参的中间意图，业务层返回 `NEED_INPUT`，不能把“合法的未补全意图”直接当可写请求。
- **CHECK** 可以没有标题，只查询会畅资源及本人预约冲突；不创建/修改会畅会议，但工具调用仍记录本地 operation/pending。
- 时间字段要求带**显式数值时区偏移**的 ISO 8601；按同一真实瞬时比较，业务服务要求未来开始和整分钟正时长。会畅接口在适配边界改为 GMT/UTC。
- `room_query` 只能是明确的 `bizvideo-room:<正整数 roomId>` 或空值；A301 等实体会议室名称不自动映射。会议方数来自可信 `MEETING_DEFAULT_PARTIES`，不是模型根据参会者数量自行决定。
- Schema 中保留 `attendee_queries` 与 `description` 等意图表达能力，**当前业务实现拒绝不支持的非空邀请名单或描述写入**。若要开放执行，必须先确认供应商能力并同步代码、测试与文档，不能静默忽略。

## UPDATE 与继续处理

UPDATE 使用统一 `time_shift_minutes` + `changes`。非零平移同时移动开始和结束时间，可以与标题等非时间字段组合；显式绝对 `start_at/end_at` 与平移互斥。未指定字段保持原值；不能恢复已废弃的 `SHIFT/PATCH` 双模式。

`continue` 中 `decision.kind` 支持 `SUPPLY_FIELDS`、`SELECT_OPTION`、`CANCEL`：补参不能借机替换认证身份，UPDATE 只能补充/替换完整 `target` 或 `update` 结构。每次继续都重新执行 Schema 与业务约束；合法 JSON 不等于有权限、不等于供应商已提交。
