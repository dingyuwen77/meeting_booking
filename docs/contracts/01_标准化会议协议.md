# 标准化会议协议

## 唯一机器契约

正式机器定义为 [src/meeting_reservation/schemas/](../../src/meeting_reservation/schemas/) 中的五份版本化 JSON Schema，校验入口为 [src/meeting_reservation/contract.py](../../src/meeting_reservation/contract.py)。本文只解释字段职责，不复制整个 Schema。

| 消息 | 职责 |
| --- | --- |
| `meeting.intent.v1` | ADP 提取 CREATE、UPDATE、CHECK、OTHER，不携带可信用户身份 |
| `meeting.request.v1` | 附加稳定 `operation_id` 后提交 |
| `meeting.continue.v1` | 以 pending ID、revision 和新操作 ID 补字段/选选项/取消待决策申请 |
| `meeting.operation-query.v1` | 查原操作状态，不重放写入 |
| `meeting.result.v1` | 所有业务 Tool 统一状态，COMMITTED 携带确认的会议摘要 |

当前仍是与 ADP/会畅租户未完成联调的 **V1 候选契约**；正式发布/冻结后有破坏性变化应发布新版本。

## CREATE / CHECK

`meeting.start_at`、`meeting.end_at` 必须为带数值偏移的 ISO 8601，内部按真实瞬时比较并转换成会畅 GMT。`CHECK` 可以不带标题，仅查询资源和当前用户已有预约。

`room_query` 不是公司实体会议室号，仅支持经业务确认的 `bizvideo-room:<数字 roomId>`；留空时由会畅选择资源。`confParties` 来自可信 `MEETING_DEFAULT_PARTIES` 配置（不是 AI 根据参会人估算）。会畅常规预约接口没有证明支持 `attendee_queries` 和 `description` 的写入，当前非空值拒绝且不静默忽略。

## UPDATE

一个统一结构：`{"time_shift_minutes":60,"changes":{"title":"新标题"}}`。相对平移同时移动起止时间；它与显式绝对 `start_at/end_at` 互斥，未指定字段保持原值。对原会议执行 UPDATE 前，MCP 先读取会畅详情、校验归属及状态、按原持续时间计算变更，再调用对应修改接口。

当同一用户多场会议的名称都与 `search_text` 相符时返回 `NEED_SELECTION`，不随机修改第一场。

## 继续处理

`decision.kind` 支持 `SELECT_OPTION`、`CANCEL`、`SUPPLY_FIELDS`。CREATE/CHECK 的补参只允许已有 meeting 字段；UPDATE 只允许完整替换 `target` 或 `update`，不得通过补参改演员身份。服务端会重新做原始 Schema 与业务检查，旧 pending 不能跳过权威冲突检查。

字段示例：[examples/](../../examples/)；契约与 CLI 回归：[tests/test_contracts.py](../../tests/test_contracts.py)。
