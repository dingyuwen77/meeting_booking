# 会议操作与状态语义

MCP 对外核心业务工具为 `submit_meeting_request`、`continue_meeting_request`、`get_meeting_operation`；另外有两个只读诊断探针 `ping_meeting_server`、`whoami_probe`。完整实现入口：[src/meeting_reservation/mcp_server.py](../../src/meeting_reservation/mcp_server.py)。

## 主链

1. ADP 根据用户文本提取候选意图，可信调用层生成在本次重试内稳定的 operation_id。
2. MCP 验证每次请求的签名身份、Schema、幂等与权限。
3. CREATE：检查必要字段、同用户已预约时段、容量及会畅资源，再由会畅最终提交；CHECK 仅读，不进行写入。
4. UPDATE：定位已授权且尚未开始的会议，回读原值，再执行单字段/组合差量修改。
5. 只有会畅提交并回读到完整详情时返回 COMMITTED；不能把仅发出请求当成功。
6. 需要用户补充/选择时生成持久 pending；会话下一轮必须通过真实 pending ID 和 revision 继续。

## 状态与调用方动作

| 状态 | ADP/调用方动作 |
| --- | --- |
| `COMMITTED` | 展示 confirmed_meeting，不凭模型原值猜会议号 |
| `AVAILABLE / UNAVAILABLE` | 展示只读检查结果，不预订 |
| `NEED_INPUT / NEED_SELECTION` | 提问/展示真实候选，传 pending ID 跨轮 |
| `CONFLICT` | 提示冲突并补充新时段；无真实候选时 options 为空 |
| `IN_PROGRESS / UNKNOWN` | 查询同一 operation_id；UNKNOWN 禁止自动二次写入，必要时人工核实 |
| `DENIED / INVALID / NOT_FOUND / FAILED / EXPIRED` | 呈现安全的错误提示，不能当成功 |
| `CANCELLED` | 仅取消待决策申请，不取消真实会议 |

## 不变项

同一 `operation_id` + 不同 payload 拒绝。所有 pending 由企业身份绑定；跨用户、过期、已使用的申请不可继续。会畅 202、205 等冲突在业务层区分；不能靠一次“先查空闲”宣称最终占用成功。

该状态定义是设计与代码目标，不代表已经通过真实 ADP、企业微信与会畅联调。测试详见 [docs/testing/01_测试与联调验收.md](../testing/01_测试与联调验收.md)。
