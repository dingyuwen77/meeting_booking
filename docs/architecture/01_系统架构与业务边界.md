# 系统架构与业务边界

## 目标

实现企业微信员工自然语言请求 → 腾讯 ADP 识别会议意图 → 固定 MCP Server 校验并执行 → 会畅智云返回真实会议。当前仓库只维护 MCP 服务及其契约，**不包含 ADP 在线工作流、企业微信渠道网关、实体会议室日历**。

## 调用链

```text
企业微信成员 UserID / 消息
  → 可信渠道/身份网关（验签、签发短时用户声明）
  → 腾讯 ADP（意图提取、状态分支、追问）
  → MCP Streamable HTTP（工具发现、调用）
  → MCP 身份验证与 Schema 校验
  → MeetingService（业务规则、冲突、操作台账）
  → BizVideoProvider（Token、表单、GMT、status）
  → 会畅 OpenAPI（权威会议事实）
  → 回读已生效详情 → 结构化结果 → ADP 回复用户
```

上述网关、ADP 工作流以及真实会畅联调为**外部待验收组成部分**；不是本仓库自建实现。

## 责任边界

- **ADP** 只负责自然语言理解与多轮界面；不能宣称会议已提交、替后端判定会议冲突或自行授予权限。
- **MCP Server** 只暴露业务 Tool，不信任工具参数中的用户身份。入口见 [src/meeting_reservation/mcp_server.py](../../src/meeting_reservation/mcp_server.py)。
- **Domain** 负责计算起止时间、差量更新、冲突检查、持久化申请和幂等，见 [src/meeting_reservation/service.py](../../src/meeting_reservation/service.py)。
- **Provider** 持有会畅账号模式 API 适配，见 [src/meeting_reservation/bizvideo.py](../../src/meeting_reservation/bizvideo.py)；不将会畅返回值直接当 MCP 公共数据格式。
- **会畅** 为真实会议、会议号、容量及提交后的最终状态来源。

## 虚拟会议资源与实体会议室

会畅 `roomId` 是其虚拟资源。业务语言的 A301/A302 是否代表企业实体会议室，目前没有相应 API 或资源映射事实，**不能将其映射为会畅 roomId**。当前输入仅接受已核验的 `bizvideo-room:<id>` 格式；公司实体会议室需未来单独确定管理系统与权限/占用事实源。

## 本次不做

不维护企业员工身份转换表（会畅 userId 直接取企微 UserID）；不自动邀请参会人，不直接管理实体会议室，不自动取消已创建的会议，不做多 Provider 实时切换，不依赖大模型执行会议写入判定。

具体字段与状态： [docs/contracts/01_标准化会议协议.md](../contracts/01_标准化会议协议.md)。
