# 部署、配置与故障恢复

## 运行边界

建议先按单实例部署，并让可信反向代理终止 HTTPS、认证来源、限制能访问 MCP 的调用方。MCP 服务自己会在每次业务工具调用中验证短时 HMAC 用户声明，但**其签名只在可信上游认证完成后才有意义**。不能把客户端自行填写的 UserID 当身份。

可使用 [Dockerfile](../../Dockerfile) 和 [compose.yaml](../../compose.yaml) 单机运行。容器内部监听 `0.0.0.0:4561`，Compose 默认只映射到宿主机 `127.0.0.1:4561`；要让 ADP 调用，仍需另行配置可信 HTTPS 网关。Compose 使用命名卷 `meeting_data` 保存 `/app/data` 的 SQLite 文件；必须备份 Docker 命名卷，不能只依赖容器可写层。

## 开启写入前的真实验收

1. 会畅测试站点/权限/容量均经过只读核实，确认 userId 确实可用企微 UserID。
2. 两个不同企业微信成员的身份签名无法相互冒用；网关不能允许任意用户指定其他 UserID。
3. 会畅 CRUD、相对/绝对修改、冲突拒绝、回读、并发和超时恢复均经过受控测试。
4. ADP 实际握手、参数/结构化结果解析与多轮恢复已通过。
5. 只有上述满足，且目标环境和权限批准，才将 `MEETING_WRITE_ENABLED=true`。首次仅对指定测试资源开放。

## 风险控制

- 持久化：SQLite 适用于单机单实例；多个主机不能各持一份操作台账。升级/迁移前备份 Docker 命名卷（本地 Python 运行则备份 `data/`），保留原 `operation_id` 和 pending 历史。
- 回滚：恢复旧服务版本、将写开关关闭；已在会畅创建的会议**不会自动撤销**。UNKNOWN 操作仍需核查，不可将回滚等于远端事务回滚。
- 故障：Provider HTTP 超时/断连会进入 UNKNOWN，禁止简单自动重发同一写操作；应由有权限的用户在会畅后台核对时间、会议名称、主持人和会议 Id。
- 日志：不要记录 Token、APIKey、签名 Header、会议密码、主持人链接或完整原始 HTTP Body。只保留无敏感内容的操作摘要和错误分类。
- 网关：必须使用可靠时钟（签名有效期约 90 秒）；签名 Header 在 HTTPS 内传递，严禁公开签名密钥或将其放在 ADP Prompt。
- 服务地址：如需内网 HTTP，只能在可信网络和上游网络隔离下使用；对 ADP 云端访问应提供 HTTPS 且有上游访问控制。

## 没有证据时不能声称

本仓库的 Fake 测试不能证明会畅原子提交、SDK MCP 在线握手、ADP 传递用户身份或真实企微 UI 行为。缺任一关键层的运行证据应在交付记录里注明，而不是写为“生产可用”。
