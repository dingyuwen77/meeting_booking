# 本地运行与调试

## 调试目标与前置条件

先证明 **JSON 契约可校验、MCP 服务可启动和只读探针可调用**，再逐层核对可信身份、会畅只读接口、受控真实写入和 ADP/企微端到端。把服务启动成功当成整条会议预约链路成功，是错误的完成判断。

项目支持 Python 3.11+、setuptools 的 `src` 包布局，安装入口与依赖见 [pyproject.toml](../../pyproject.toml)。建议在仓库根目录使用独立虚拟环境，不需要将本机 Python 安装路径硬编码到文档。

## 1. 安装和本地契约验证

```bash
python -m venv .venv
# Windows PowerShell 激活：.\.venv\Scripts\Activate.ps1
# Linux/macOS 激活：source .venv/bin/activate
python -m pip install -e ".[dev]"
python -m meeting_reservation validate-examples --dir examples
python -m meeting_reservation validate intent examples/create.intent.json
```

还可以在虚拟环境使用 `meeting-contract validate intent examples/create.intent.json`。以上命令调用 [src/meeting_reservation/cli.py](../../src/meeting_reservation/cli.py) 的正式校验入口，**不进行会畅订会、查询或 MCP 网络调用**；成功退出码为 0，校验/输入错误为 2。

## 2. 启动 MCP 服务与探针

```bash
python -m meeting_reservation.mcp_server
# 本机默认监听 127.0.0.1:4561，URL 为 http://127.0.0.1:4561/mcp
```

亦可执行已安装的 `meeting-mcp` 入口。应使用兼容 Streamable HTTP 的 **MCP Client/Inspector** 调用 SDK `initialize`、`tools/list`、`tools/call`；不是向 `/mcp` 发送任意 REST JSON POST。

1. 默认发现五个工具，并调用免身份 `ping_meeting_server`。此探针不需要会畅 `APIKey`、`siteSign`；临时参数探针须单独开启。
2. 用隔离测试的可信网关签名请求调用 `whoami_probe`；未带签名应被拒绝。动态 Header 格式详见 [docs/architecture/02_身份认证与操作状态.md](../architecture/02_身份认证与操作状态.md)；不要复制生产密钥或签名进测试记录。
3. 在 Fake/HTTP Mock 测试中练习 CREATE、CHECK、UPDATE、pending、UNKNOWN；不要为了“验证程序”开启真实写入。
4. 只有取得测试站点、权限和业务批准后，才验证会畅真实只读查询，再评估受控真实写入。平台级验收步骤见 [docs/testing/01_测试与联调验收.md](../testing/01_测试与联调验收.md)。

## 3. 配置如何生效

[.env.example](../../.env.example) 是脱敏模板；[src/meeting_reservation/settings.py](../../src/meeting_reservation/settings.py) 直接读取进程环境变量，**本地 Python 不自动加载 `.env`**。Shell、IDE 运行配置、服务管理器或容器应在进程启动前注入配置。

| 变量 | 目的及限制 |
| --- | --- |
| `MEETING_CORP_ID`、`MEETING_IDENTITY_SECRET` | 验证可信签名的企业身份；共享密钥至少 32 字符，只存于可信端 |
| `MEETING_IDENTITY_PROBE_ENABLED`、`MEETING_IDENTITY_PROBE_KEY` | 临时参数探针，默认关闭；显式 `true`（大小写不敏感）开启时要求至少 32 个非空白可打印 ASCII 字符的独立随机密钥 |
| `MEETING_SITE_SIGN`、`MEETING_API_KEY` | 会畅真实访问所需站点/密钥；无凭据仍可 ping |
| `MEETING_BIZVIDEO_BASE_URL` | 会畅 HTTPS OpenAPI 地址；配置检查禁止非 HTTPS |
| `MEETING_DEFAULT_PARTIES` | 服务端指定会议方数；模板值 25 不表示实际站点支持 |
| `MEETING_HTTP_TIMEOUT` | 供应商请求超时秒数，应大于 0 |
| `MEETING_DB_PATH` | SQLite 持久文件路径，启动时会建父目录与表 |
| `MEETING_WRITE_ENABLED` | 默认 false；仅显式字符串 `true` 启用真实写入 |
| `MEETING_MCP_HOST`、`MEETING_MCP_PORT` | MCP 监听主机/端口；本地默认 127.0.0.1:4561 |

生产凭据不得写入 Git、日志、示例或临时公开脚本。对于指定 `room_query`，只允许会畅的虚拟 `bizvideo-room:<roomId>`，不能把实体会议室名当资源 ID。

### 临时参数探针的本地运行

只验证 UserID 参数传递时，可以使用临时 `identity_binding_probe`，无需配置会畅、企业 CorpID 或 HMAC 密钥。其配置独立于业务 `Settings`，也不会初始化业务服务。以下 PowerShell 命令生成仅保留在当前进程环境中的随机密钥并启动服务；若已有安全保存的 POC 密钥，应从安全来源注入同一值：

```powershell
$env:MEETING_IDENTITY_PROBE_ENABLED = "true"
$env:MEETING_IDENTITY_PROBE_KEY = python -c "import secrets; print(secrets.token_urlsafe(32))"
$env:MEETING_WRITE_ENABLED = "false"
python -m meeting_reservation.mcp_server
```

用兼容 Streamable HTTP 的客户端连接本机 `/mcp`，在 HTTP Header 中注入与服务环境一致的 `X-Meeting-Identity-Probe-Key`，先初始化并发现工具，再调用 `identity_binding_probe`，参数示例为 `{"actor_user_id":"EMPLOYEE_A"}`。UserID 复用现有规则：1–128 个 ASCII 字母、数字、`_@.-`，原样回显，不裁剪空白。返回值与 ADP 后续验证见 [docs/integrations/02_腾讯ADP与MCP接入.md](../integrations/02_腾讯ADP与MCP接入.md)。

开关和密钥在服务构造时读取；开启但密钥缺失或不合格会拒绝启动，错误不回显密钥。修改环境后须重启；关闭时忽略遗留探针密钥，工具不在列表中，也不可直接调用。POC 结束设置 `MEETING_IDENTITY_PROBE_ENABLED=false` 并重启，移除客户端绑定与密钥。不要复用正式 HMAC 或供应商密钥。

## 4. 本地回归入口

在已安装开发依赖的环境中：

```bash
python -m pytest -q
python -m ruff check src tests
python -m compileall -q src
python -m meeting_reservation validate-examples --dir examples
```

`pytest` 使用 Fake/HTTP Mock、真实本地 SQLite 和 MCP SDK ASGI 测试，**不会等同于远端会畅或腾讯 ADP 验收**。测试代码对应关系见 [docs/architecture/03_代码结构与调用链导航.md](../architecture/03_代码结构与调用链导航.md)。

## 5. 排障顺序

按照 **CLI/Schema → MCP ping → 身份探针 → Fake/Mock → 会畅只读 → 授权写入 → ADP/企微** 的依赖顺序逐层排查。某一步失败，不要通过打开写入开关或换 operation_id 试错。日志、环境、SQLite、HTTP 421/UNKNOWN 的具体诊断见 [docs/operations/03_故障排查与恢复.md](03_故障排查与恢复.md)。Docker 与代理配置见 [docs/operations/02_部署配置与运行维护.md](02_部署配置与运行维护.md)。
