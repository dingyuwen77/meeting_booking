# 本地运行与调试

## 1. 安装

建议 Python 3.11+ 和专用虚拟环境，避免依赖 Windows 本机特定 Python 路径：

```bash
python -m venv .venv
python -m pip install -e ".[dev]"
python -m pytest -q
python -m ruff check src tests
python -m meeting_reservation validate-examples --dir examples
```

虚拟环境激活、平台路径按所在机器选择。项目保留 `python -m meeting_reservation`、`meeting-contract` 的既有 Schema 验证能力，入口见 [src/meeting_reservation/cli.py](../../src/meeting_reservation/cli.py)。

## 2. 本地 MCP

```bash
python -m meeting_reservation.mcp_server
# 默认服务监听 127.0.0.1:4561，MCP URL 为 http://127.0.0.1:4561/mcp
```

MCP 不是普通 REST JSON POST 接口：请用官方 MCP Client 或 Inspector 发起 initialize/tools/list/tools/call。先调用 `ping_meeting_server`，无须任何会畅凭据；身份测试通过 `whoami_probe`。业务工具必须在服务器配置站点、API Key、可信网关密钥之后才能调用。

本地可借助 Python 测试 Fake Provider 验证请求与状态机，避免测试命令误创建真实会议。会畅实时测试必须在业务方授权的沙箱资源上进行，并标明测试使用的 userId、siteSign 和会议 Id（报告中脱敏）。

## 3. 配置

[.env.example](../../.env.example) 是模板，不会自动被 Python 加载，也不应包含实际 Secret。通过 shell、服务管理器或容器环境文件设置变量。重要配置：

- `MEETING_CORP_ID`：企微企业 ID，用于身份隔离；
- `MEETING_IDENTITY_SECRET`：与可信网关共享的随机密钥，至少 32 字符；
- `MEETING_SITE_SIGN`、`MEETING_API_KEY`：会畅站点及权限凭据；
- `MEETING_DEFAULT_PARTIES`：明确选定的会畅会议方数，默认示例 25 **并不证明实际站点支持**；
- `MEETING_WRITE_ENABLED`：只有字符串 `true` 才打开创建/修改；默认关闭；
- `MEETING_DB_PATH`：本地持久化 SQLite 路径，务必有写权限和备份；
- `MEETING_MCP_HOST`、`MEETING_MCP_PORT`：监听地址和端口。

## 4. 调试顺序

Schema/例子 → Fake Provider 行为 → 只读 MCP 握手 → 可信身份探针 → 会畅只读资源/会议详情 → **用户批准的受控真实写入** → ADP 业务流程/企微端到端。任何层失败时先定位具体入口，不用下游操作掩盖上游未通过的门禁。

主要测试：[tests/test_booking_service.py](../../tests/test_booking_service.py) 与 [tests/test_contracts.py](../../tests/test_contracts.py)。
