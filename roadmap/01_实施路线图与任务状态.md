# meeting_booking 当前实施状态与验收门禁

## 1. 目标与范围

交付范围为 **腾讯 ADP 调用的 Python MCP 会议业务服务**：正式 JSON 契约、可信企业成员身份、会畅账号模式 API 适配、CREATE/CHECK/UPDATE、多轮 pending、SQLite 操作台账和可恢复的结果查询。

**不在本仓库实现**：企业微信网关、ADP 租户画布、实体会议室预订、自动邀请、会议描述写入、已创建会议取消、多 Provider、分布式部署或生产发布。企微 UserID 原样复用为会畅 `userId`，但可信网关必须独立验签。

下列 R 编号承接既有需求，避免因整理文档丢失验收边界。测试执行方法见 [docs/testing/01_测试与联调验收.md](../docs/testing/01_测试与联调验收.md)。

| ID | 要求 | 通过前还需重点核实 |
| --- | --- | --- |
| R01 | 原样使用企微 UserID、但不得伪造身份 | 真网关验签、不同员工隔离 |
| R02 | CREATE Token/form/GMT、远端提交与回读 | 会畅真实预约、详情完整性 |
| R03 | CHECK 不执行会畅写操作、检查本人重叠 | 资源查询和时段规则 |

| R05 | 虚拟 roomId 不混同实体 A301 | 真实虚拟资源预约与修改 |
| R06 | pending 补参、选项、取消、跨用户隔离 | ADP 跨轮状态传递 |
| R07 | 同一 operation_id 不重复写入 | 调用层稳定 ID、真实并发限制 |
| R08 | UNKNOWN 不盲重放、允许核实原操作 | 实际超时/断连与人工对账演练 |
| R09 | MCP 入参/结构化结果可被调用方消费 | ADP 租户握手、结构化输出 |
| R10 | 文档和当前代码、测试、配置一致 | 路径、语义、链接、示例审计 |
| R11 | 包、CLI、SDK、容器具备可运行证据 | 对应 revision 的安装、启动或测试记录 |
| R12 | PR、权限、检查、合并及 main-fresh 收尾 | 每次交付读取当前平台真实状态 |

上一轮实现 PR [#1](https://github.com/dingyuwen77/meeting_booking/pull/1) 是历史交付证据，**不代表下一次文档/代码改动已经验收或合并**。

## 4. 交付、生产启用和恢复不是同一门禁

- 仓库交付：按项目 [AGENTS.md](../AGENTS.md) 核对需求、变更、相关验证、PR 和合并后 revision。仓库当前无 Actions 工作流，不得将“无 required check”写成“CI 通过”。
- 真实写入启用：首先取得会畅测试站点/API 权限、可信身份动态透传、ADP 结构化结果、多轮与企微端到端的独立证据，再经环境授权开启写入；仅合并代码不构成授权。
- 运行恢复：SQLite 可查询本地 `operation_id` 结果，但会畅写入结果不确定时不能自动重放。UNKNOWN 人工核实和备份/回滚方法见 [docs/operations/03_故障排查与恢复.md](../docs/operations/03_故障排查与恢复.md)。
- 当前服务只有启动建表，没有版本化数据库迁移工具；保留操作历史，回滚服务不会撤销会畅已创建会议。
